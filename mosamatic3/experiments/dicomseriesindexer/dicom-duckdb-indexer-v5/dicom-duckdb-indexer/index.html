Collections and indexing

Checked (default): prefer folder_patient_id, with DICOM PatientID as a fallback. Unchecked: prefer DICOM PatientID, with the folder ID as a fallback. This setting is saved per collection and also applies to already indexed series.

Choose a root containing patient folders (any nesting) and/or ZIP archives. If you close this tab, choose the same root again to resume. Pausing keeps all committed batches in DuckDB.

Large datasets: allow sufficient browser quota; use local disks, not network mounts when possible. This indexes metadata without extracting pixel data. Uncompressed multi-terabyte datasets still require substantial I/O.
Collection reset / reindex

Useful query / export notes

number_of_instances counts unique SOP instances; number_of_frames sums DICOM frames, which can exceed instances for multi-frame data. The duplicate_sources view lists every source occurrence for repeated SOP Instance UIDs. scan_type is the predominant image type; secondary counts and scan_types_present remain available.

Phase and delay are heuristic. Delay is computed using the mean slice acquisition timestamp minus ContrastBolusStartTime; ambiguous, absent, or implausible bolus values yield NULL. Neither series folders nor original ZIPs are copied into the database.
